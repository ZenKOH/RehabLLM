# v0.2 corpus-quality pipeline

v0.2 moves RehabLLM from “raw PMC text can be fetched” to a reproducible corpus build with explicit quality, rights, deduplication and split controls.

## Pipeline

```text
PMC discovery
  ↓
article-level rights verification (OAI-PMH dc:rights)
  ↓
BioC full text retrieval
  ↓
quality filters
  ↓
exact SHA-256 deduplication
  ↓
5-word-shingle MinHash/LSH candidate search
  ↓
exact Jaccard confirmation
  ↓
document-level deterministic train/val/test split
  ↓
SentencePiece trained on train only
  ↓
train.bin / val.bin / test.bin
```

## Why document-level splitting matters

Random token-window splitting can put passages from the same article into both train and evaluation sets. v0.2 assigns each PMCID deterministically to one split before tokenisation, reducing leakage.

## Deduplication

The deduplicator first removes byte-normalised exact duplicates. Near duplicates use 5-word shingles, a 64-permutation MinHash signature and 16 LSH bands to generate candidate pairs. Candidate pairs are then checked with exact shingle Jaccard similarity. The default threshold is 0.82.

This is deliberately inspectable rather than optimised for billion-document corpora. If the project grows substantially, replace the local implementation with a distributed pipeline such as DataTrove while preserving the manifest contract.

## Quality filters

Default hard filters remove documents that are extremely short/long, symbol-heavy, low in alphabetic words, have implausible median word length, or contain excessive duplicate lines. Thresholds live in `configs/curation.yaml` and should be treated as experiment parameters, not universal truths.

## Rights controls

Search filters are not treated as the final licence record. The fetcher obtains OAI-PMH Dublin Core metadata and records `dc:rights` for each article. The v0.2 default allow-list remains:

- CC0
- CC BY
- CC BY-SA

Anything else is skipped by default.

## Research integrity filters

The PMC query excludes:

- retraction notices;
- articles marked as retracted;
- expressions of concern;
- articles with a published expression of concern;
- correction notices;
- embargoed records.

Corrections to an otherwise valid article are not automatically treated as retractions; the corpus policy can be tightened later if required.

## Reproducibility artefacts

`curate_corpus.py` writes:

- `articles.jsonl` — accepted records with metrics, split and hashes;
- `rejected.jsonl` — rejected records and reasons;
- `stats.json` — corpus counts and rejection profile;
- `manifest.json` — input SHA-256 plus curation configuration;
- `train.txt`, `val.txt`, `test.txt` — document-level split text.

Training writes `run_manifest.json` with model/training config, Git commit, Python/PyTorch versions and SHA-256 hashes of tokenised training/validation data.
